# 本地基金分类候选

`src/fund-suggestions.mjs` 导出纯函数 `suggestFund(row)`。只读取可选字符串字段 `name`、`code`，无联网、远程请求、存储或截图上传。返回：

```js
{ category: null, sectorIds: [], benchmarkIds: [], basis: [],
  confidence: 'unknown', canonicalName: null }
```

分类候选值为 `权益`、`固收`、`现金`、`黄金`、`混合`。`confidence` 只表示证据来源（`exact-code`、`name-keyword`、`unknown`），不代表识别正确率或投资风险。`canonicalName` 暂时始终为 `null`，因为本模块没有经过实时核验的正式基金全称库。

## 有限规则

- 精确字符串代码仅支持 `512480 → semiconductor`、`512170 → medical`、`515030 → ev`。这是三条本地行业参考关系，不是完整基金数据库，也不代表实际组合穿透结果。
- 名称明确包含 `半导体/芯片`、`医疗`、`新能源车/新能源汽车`，分别提供上述三个行业候选。`医药/生物科技 → pharma`，与 `医疗 → medical` 分开；`新能源` 不等同 `新能源汽车`，也不推断为传统能源。
- 明确的地区科技词提供 `美股科技/美国科技/美国信息科技 → us-tech`、`港股科技/恒生科技 → hk-tech`、`A股科技 → cn-tech`。不从全球、QDII 或纳斯达克100泛化为美股科技行业。
- 其他明确主题提供 `人工智能 → ai`、`软件/云计算 → software`、`互联网 → internet`、`消费 → consumer`、`能源（排除新能源词）→ energy`、`金融/银行 → financials`、`制造 → industrial`、`房地产 → real-estate`、`全球股票/全球精选股票 → global-equity`。同一主题的多个关键词只产生一个候选。
- 非矿业的黄金产品提供 `gold`，明确债券产品提供 `bond`，货币基金等明确现金类型提供 `cash`。普通混合基金可以提供明确名称主题，但不推断其权益比例。
- 名称明确包含 `沪深300`、`创业板指数/创业板ETF`、`恒生指数/恒生ETF`、`标普500`、`纳斯达克100`、`黄金`，分别提供 `cn-large`、`cn-growth`、`hk-broad`、`us-broad`、`us-tech`、`gold-us` 参考候选。这些是名称词匹配，不证明基金实际跟踪关系；黄金的美元市场参照也不改变持仓币种。
- 同样通过变体检查的沪深300、标普500、恒生指数名称另提供 `cn-broad`、`us-broad`、`hk-broad` 市场主题候选。纳斯达克100只提供基准候选，不直接把全部持仓归为科技行业。恒生科技提供港股科技主题，不继承恒生宽基参照。
- 恒生科技/国企、创业板50/200/成长及红利、等权、低波等变体不继承母指数。黄金股、黄金产业、黄金矿业等权益主题不映射黄金类别或黄金价格参照。`半导体债券` 等行业或权益指数与债券类型冲突时保持未知。`自由现金流ETF` 不归现金；只有货币基金/货币市场基金、现金管理或明确“现金”才提供现金候选，数字/加密货币不参与此规则。
- `纳斯达克` 泛称、`纳指生物` 不补为 `纳斯达克100`。不模糊补全被截断的名称，也不修改 OCR 文字、代码或基金名称。
- 明确的债券、货币基金/现金管理、黄金、股票、混合名称词提供对应类别；ETF/指数仅在没有上述明确类型时提供权益候选。货币基金归为现金只是工作台分类候选，不表示等同银行现金。稳健、成长或风险词不生成类别。
- 多个明确类别相互冲突，或精确代码与名称中的其他行业、明确基准、非权益类别相冲突时，整条返回 `unknown` 和空候选，依据说明冲突，要求人工核对。
- 最多提供三个不同的明确主题；命中四个或更多时返回 `unknown` 和空候选，并说明候选过多、存在不确定性，不静默截取前三项。债券自身的 `bond` 主题不构成权益行业冲突。
- 未知代码、币种、代码形状、账户名称不参与推断。不将人民币基金直接映射为中国大盘，也不推断风险或收益。

## 调用边界

每次返回独立数组，不修改入参，不设置 `reviewStatus`、`sectorReview` 或 `benchmarkReview`，不直接写入正式分类。调用方只能把结果作为候选展示，用户主动应用后仍须核对并确认。依据文字始终区分本地代码参考与名称关键词，并明确“不是穿透持仓分析”。

## 验证

`node --test tests/fund-suggestions.test.mjs` 覆盖三个精确代码、扩展主题和地区科技边界、医药与医疗区分、最多三个主题和超额未知、明确名称与基准、泛称和截断名称、类别冲突、代码名称冲突、币种不推断、异常输入及输入不变性。测试名称为虚构规则样例，不声称核验过实际基金。`npm test` 为项目完整单元回归入口。UI 由调用方单独验证，本模块测试不构成 OCR 准确率或真实截图识别验收。
