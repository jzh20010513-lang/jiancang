## 1. 产品定位与决策依据

面向希望看清自己资产分布、又不愿将持仓截图交给云端的个人用户，提供一个无需注册的网页工具：在浏览器本地识别截图，经过用户核对，生成可自定义的持仓看板。

核心承诺：截图、OCR 原文与持仓内容不上传；数字可核对；缺失信息不伪装为零或精确结论。

### 1.1 用户已经确认

- 用户通过网站使用，截图是优先导入方式。
- 截图始终由用户本地处理，不采用云端识别，不建设云端持仓数据库。
- 第一版无需跨设备同步；换设备可以重新导入。
- 信息不完整时不显示历史收益率等无法可靠计算的指标。
- 为用户保留 DIY 空间。
- 与现有个人版严格隔离，不影响其运行，不使用开发者真实隐私数据。

### 1.2 本文建议默认值

以下是可调整的产品设计，不代表用户逐条确认：默认会话内使用，主动选择后才在当前浏览器保存；DIY 限于声明式配置；首发无实时行情、账号、分享链接和遥测；每次导入整组替换当前快照。具体截图平台与 OCR 支持质量须先验证，不承诺全平台。

### 1.3 方案比较

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| 下载运行本地应用 | 本地控制充分 | 安装门槛较高，作为后续可选形态 |
| 在线访问、浏览器本地处理 | 无需安装且不接收持仓 | 需要本地 OCR 与人工核对，选为本版方向 |
| 在线访问、云端识别和保存 | 便于同步及服务端处理 | 不符合截图留在用户设备的要求，本版排除 |

## 2. 目标、非目标与完成定义

### 2.1 本版目标

1. 用户在不注册、不上传截图的情况下完成导入。
2. 用户能确认金额、币种、资产名称及数据日期，再生成看板。
3. 即使 OCR 无法识别，仍能通过手动补录完成使用。
4. 用户能调整卡片、分类和标签，导出自己的数据及布局。
5. 新应用可以作为独立静态产物部署，与个人版不存在运行依赖。

### 2.2 明确不做

云端账户和同步、自动交易、证券账户连接、投资推荐、历史收益率及收益曲线、基金底层穿透、自动汇率换算、实时行情、云端 OCR、任意代码插件、在线分享持仓、自动截图上传诊断、截图原图持久保存。

### 2.3 完成定义

完成技术文档中的隐私、计算、导入、存储、浏览器与隔离验收；对外列明已测试版式、设备和限制。文档完成、识别演示成功或静态页面能打开，均不等于产品发布验收完成。

## 3. 用户场景与主流程

### 3.1 场景

- 只上传一个账户：查看“已导入资产”，不声称覆盖全部资产。
- 上传多个账户截图：核对后比较同币种下的账户和资产分布。
- 识别效果不好：在截图旁编辑结果，或直接手动录入。
- 不想保留数据：会话内使用，关闭后不由应用主动持久保存。
- 想下次继续：主动启用本机保存；换设备通过导出文件迁移。

### 3.2 页面和状态

| 步骤 | 用户看到什么 | 关键动作 |
| --- | --- | --- |
| 首页 | 本地处理说明、虚构示例、开始导入、手动录入 | 不要求注册；不自动载入示例为真实资产 |
| 文件选择 | 缩略图、大小校验、裁剪与删除入口 | 多图分批处理，可取消 |
| 识别 | 模型准备与逐图进度 | 模型下载失败时提供重试和手动录入 |
| 核对 | 截图局部与可编辑表格、疑点及遗漏提示 | 确认字段、日期、重复项、账户和收录范围 |
| 应用预览 | 新旧行数及各币种合计对比 | 明确整组替换；确认前不影响当前看板 |
| 看板 | 已导入资产、分布、集中度、完整性提示 | 调整布局、筛选、修改分类、导出 |
| 数据管理 | 保存状态、导出、清除本机数据 | 保存失败不得显示“已保存” |

首版每个导入批次形成一个当前快照。多图可以在同一批次中整理；新增批次默认替换整个当前快照，禁止无提示追加。不保存历史快照序列，不生成跨期趋势。

## 4. P0 功能需求

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| IMP-01 | 本地多图导入 | PNG/JPEG/WebP；拒绝 SVG、PDF、动图及不能解码的文件；不发送图片 |
| IMP-02 | 裁剪与方向调整 | 用户可去掉姓名、账号等无关区域；只改内存中的副本 |
| OCR-01 | 本地 OCR | 页面保持可操作，显示阶段，支持取消；失败后可手动录入 |
| REV-01 | 人工核对 | 所有金额、币种、名称、日期均可编辑；低置信字段提示但不以分数代替确认 |
| REV-02 | 缺失与冲突 | 缺币种或金额不得进入合计；保留待补行并展示排除数量；冲突不自动猜选 |
| REV-03 | 重复候选 | 同图重复和跨图重叠提示；由用户决定保留，不能静默删除真实重复持仓 |
| REV-04 | 日期与覆盖 | 上传时间单独记录；用户确认持仓日期；混合日期显著提示 |
| DASH-01 | 看板 | 按币种展示已导入资产、账户分布、类别分布、集中度及未计入项 |
| DIY-01 | 卡片与布局 | 排序、显隐、恢复默认，桌面与手机均有按钮操作，不依赖拖动 |
| DIY-02 | 个性化分类 | 账户别名、自定义资产类别、标签、关注标记；未分类独立保留 |
| DATA-01 | 本机保存 | 默认不持久保存；主动开启后保存用户确认应用的快照和布局，含明确保留的待补行，不保存原图/OCR 原文 |
| DATA-02 | 导出和恢复 | JSON 携带数据、版本及布局；导入校验、预览、确认后替换 |
| DATA-03 | 清除 | 可分别清除业务数据、重置布局；撤销保存授权时说明是否同时删除旧数据 |
| HELP-01 | 说明与反馈 | 公开算法说明、支持版式、隐私边界；反馈不自动附带用户内容 |

导入限制建议：单图不超过 10 MiB、单批最多 10 张、单图解码不超过 2000 万像素、单批原文件累计不超过 50 MiB；超过时明确拒绝并建议裁剪/分批。数值是待设备验证的设计上限，不是已验证性能。

## 5. DIY 的空间与边界

### 5.1 首版提供

- 卡片顺序和显隐、浅色/深色主题、金额遮罩、紧凑/舒适密度。
- 账户自定义别名，资产分类和标签，按账户/类别/标签筛选。
- 显示字段的选择；未确认、排除计入和日期状态不能隐藏到无迹可寻。
- 导出“仅布局配置”，不包含资产名称、金额、账户别名、自定义分类名或标签，便于安全复用。

### 5.2 后续可做

声明式截图字段映射模板、用户自定义观察阈值、更多图表、手动 CSV 导入。须独立验证其隐私和计算边界。

### 5.3 不开放

任意 JavaScript/HTML/CSS 注入、远程插件 URL、联网模型、自定义可执行公式。首版主题采用固定令牌；用户不能通过 DIY 改写收益定义或去掉数据来源说明。金额遮罩只保护屏幕展示，不是存储加密。

## 6. 数据字段与计算口径

每行至少支持：本地行 ID、账户别名、名称、可选代码、币种、持仓金额、数据日期、资产类别、标签、来源类型与确认状态。单位/小数点/负号/“万”“亿”必须保留核对线索。

可选字段包括截图明确标注的持有收益金额、当日收益金额和其币种/日期；原始百分比只在本次核对页按原标签展示，不持久保存，也不进入应用后的看板。无法确认含义的数字不作为财务字段入库。

用户可明确选择将字段不完整的行作为“待补行”一起应用；此类行随快照保存、导出和恢复，始终排除计算，并在看板提供补录入口。只有用户核对过的字段才进入快照，不明确的识别候选置空。整批尚未确认应用的 OCR 草稿不保存，原文与截图也不会随待补行保存。

| 指标 | 规则 |
| --- | --- |
| 已导入资产合计 | 同币种、已确认且金额非负的持仓求和；缺失、负资产和未确认行不计入并说明原因 |
| 分布占比 | 每个币种、当前筛选范围的有效金额作分母；页面注明筛选与分母，不使用“全部家庭资产”措辞 |
| 集中度 | 按用户确认的同一资产分组；仅有同名不自动合并；无法确认时称“单条持仓占比” |
| 负资产 | 首版不支持负债、杠杆及空头计入；标为不支持，可保留待处理，不截断为零 |
| 零值 | 明确识别或手填确认的零才是零；分母为零时不显示百分比 |
| 多币种 | 各币种分开展示，不自动推断“$”一定为美元，不提供跨币种总额 |
| 日期混合 | 保留每行日期；合计标记为混合日期快照，不称当前实时资产 |
| 收益 | 显示单行用户确认的截图报告值及标签；首版不汇总收益、不推算年化和历史收益率 |

资产类别是用户整理标签，不等于专业风险评级。看板用于记录与理解数据，不生成买卖动作。

## 7. 隐私和个人版隔离

- 截图、识别文字、资产、金额、标签、文件名不得进入 URL、服务器日志、遥测或错误上报。
- 模型、字体、脚本、样式统一从独立站点同源静态目录加载；不引入第三方统计或远程 CDN。
- 站点托管方仍可能记录普通访问的 IP、时间和静态资源路径。隐私说明准确区分访问日志与持仓数据，不承诺匿名访问。
- 浏览器本机存储不是加密保险箱。共享设备、浏览器扩展、设备恶意软件及站点脚本被篡改仍是风险。
- 不读取或复制个人版私有目录、运行状态、验证截图、旧发布快照、历史工作记录或真实配置。
- 后续公开版使用独立工程目录、依赖、构建产物、开发端口及托管源；不得复用个人版服务、现有公开演示站点或其 Service Worker 范围。
- 仅使用人工构造的截图和数据进行开发；真实测试样本须另行明确授权且不得进入仓库。

## 8. 异常与恢复

| 异常 | 预期行为 |
| --- | --- |
| 识别出空结果 | 保留当前会话截图供核对，提供手填，不生成虚假持仓 |
| 识别中取消 | 停止工作线程，丢弃本次草稿，原看板不变 |
| 文件过大/内存不足 | 拒绝或终止当前任务，建议裁剪，保留已确认看板 |
| 本地存储不可用/配额不足 | 显示仅本次会话可用，提示导出，不伪报保存成功 |
| 刷新页面 | 会话草稿可能丢失；有未保存修改时尽力提醒，不承诺浏览器一定拦截关闭 |
| 恢复文件版本较新/损坏 | 拒绝覆盖，说明原因；原数据保持不变 |
| 清除数据 | 删除本应用存储及内存引用，不删除用户原始文件；不承诺磁盘取证级擦除 |

## 9. 交付阶段与验收

1. **可行性验证**：人工合成至少 30 张截图，涵盖至少三种通用版式及模糊、重叠、多币种、截断等失败场景。统计字段识别准确率、耗时、内存；选定首发支持范围。不得把人工核对后的正确率当 OCR 原始准确率。
2. **MVP**：完成所有 P0、手动兜底、DIY、导出恢复和隐私验收。建议选择至少两种实际验证通过的版式；若效果不达标则收窄支持范围，不改为云端识别。
3. **公开测试**：补充使用文档、许可证、依赖声明、独立构建及发布检查；用户明确授权后才创建远程仓库或部署。

关键发布门槛：持仓内容外发为零；确认后的有效数据与确定性测试结果一致；失败导入不覆盖旧数据；原图不进入持久存储；布局配置导出不带业务数据；个人版文件无变更。性能目标和浏览器兼容范围由第一阶段实测锁定，不预先声称支持所有设备。

产品成功指标以人工可用性测试衡量：首次完成导入的比例、核对修改量、错误恢复成功率、对分母与日期含义的理解。首版不通过线上遥测收集这些指标。

## 10. 待验证项与设计默认

- 支持平台/截图格式：使用合成版式先验证，随后按实际测试列白名单；不以品牌名代替兼容性证据。
- OCR 引擎和模型：由技术试验选择，须满足浏览器本地运行、同源托管与可分发许可。
- 移动端：为目标体验，发布支持范围须实测；桌面不通过也不得用移动端延期掩盖。
- 开源许可证：发布前由项目所有者决定，文档不代作授权。
- 本文不授权开发、服务重启、分支合并、创建远程仓库或发布；后续按用户明确指令推进。
