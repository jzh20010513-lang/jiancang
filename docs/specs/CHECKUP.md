# 持仓体检与个人目标对照

2026-10-26｜用户已确认按此方向实现，保留原截图本地处理、个人版隔离和不发布边界。

## 产品目标
用户导入后获得“先检查什么、依据是什么、下一步怎样核对”，而非仅看图表。核心为用户自定标准下的持仓体检，不设通用健康分，不推荐具体产品或预测行情。

## 已选方案
采用浏览器本地透明规则引擎。在线AI分析不符合隐私要求；只增加可视化仍未解决用户价值问题。规则依赖用户目标、已确认持仓和明确缺失项，不推断风险承受能力或基金底层敞口。

## 本轮范围
- 用户填写用途、币种、类别目标比例（合计100%）、偏离提示阈值、单资产占比上限、需要可用的金额和日期；全部可不设置，不提供默认适配全人的配置。
- 目标按类别名称精确匹配，类别更名/消失后标为未匹配；不因截图替换时生成新ID而丢失对照。
- 持仓增加用户标注的流动性（未知/当前可用/受限）和可选解锁日期、同一资产分组。标签不等于真实赎回承诺。
- 检查数据缺失/混合日期、配置偏离、集中度、相同代码或已确认资产分组、用钱目标与已标注可用金额/受限期限。
- 体检固定使用全部已导入持仓，明确不随图表筛选改变。未知资产仍保留，缺失影响结论时不宣称达标。
- 优先级只代表核对顺序，列出证据、来源类型和下一步，提供直达编辑持仓/设置目标的入口。
- 保留一个上次导入快照，分币种对照金额/类别变化；导入范围可能不同，不解释为收益。仅编辑当前持仓不滚动对照基线；备份恢复不假装一次真实持仓更新。
- 目标、流动性和上次快照包含在完整备份中，仍默认会话内存；纯布局不包含这些内容。兼容v1备份，新版完整备份使用v2。

## 逻辑schema
`plan={purpose:string,rules:[{currency,allocations:[{category,percent}],deviationThreshold,maxSinglePercent,requiredLiquid,needBy}]}`。
百分比与金额都是规范十进制字符串；可选字段null；deviationThreshold缺省建议5但用户需看到并确认，不是行业标准。每币种一条规则，类别不重复，配置目标若非空必须合计100%。不设置的检查不运行。
`planning={plan,previousSnapshot:null|Snapshot,dataKind:'user'|'demo',planSource:'none'|'demo'|'user'}`。规则来源与持仓来源分开；真实导入清空未确认的演示规则，显式保存的用户目标保留。旧v2缺省来源按数据类型保守恢复；v1没有目标。
持仓可选`liquidity:'unknown'|'available'|'locked'`和`unlockDate:null|YYYY-MM-DD`。仅locked可有解锁日期。

## 验收
- 自定目标与实际偏离、零目标、未知类别、不完整数据、负资产、零分母、多币种、资产分组和代码重复都具确定测试。
- 未知流动性不能算可用；预计解锁不冒充现金，来源日期混合时提示；未设置目标不生成臆测建议。
- 日期以浏览器本地日历/用户明确日期为依据，不偷偷推断时区。
- 配置校验失败不丢输入；持久化失败不覆盖旧目标或快照；v1恢复后无虚构目标。
- 截图/目标/持仓不外发，所有输入按纯文本显示；金额遮罩同时覆盖体检证据和对照金额。
- 首屏呈现有用的检查理由，不输出买卖金额、保证收益或伪造穿透。
- 没有持仓也可先保存并导出目标；没有已确认资产时，即便用钱目标为零也不报“覆盖已达标”。

## 设计
沿用现有蓝白视觉。首屏改为体检摘要、优先检查事项和目标偏离表；金额明细保留在下方。无目标时引导设置标准，同时仍展示数据完整性问题。示例明确为虚构，带演示目标以帮助用户理解功能。
