最新补充：[支付宝同列错配复核](ALIPAY_PAIRING_REVIEW.md)。下文早一轮的“实际截图尚未复测”是历史状态；本轮已用实际页面OCR原文验证6条名称/金额配对，但仍没有重新运行实际原图OCR，不能据此宣称原图字符准确率。

## 2026-10-27 解析修正后复测

新增金额列与收益列分离、保留基金名称内指数数字、独立金额行、明确A/C/LOF续行、坐标列匹配及内存内图像放大。完整重跑原36张合成图108条真值：金额、币种、金额+币种各正确107/108（precision/recall均99.07%）；名称91/108（84.26%）；完整行90/108（83.33%）；0引擎异常。金额错误仍在水印重叠图，名称的截断、低对比和错字仍是明显限制。这不是支付宝真实截图准确率。

另用程序绘制的支付宝风格多列图实跑浏览器OCR：两条虚构基金名称、持仓金额、人民币均正确，收益和收益率未被作为持仓金额。只验证这一张合成图，不代表完整平台兼容。新增入口 `node tests/alipay-ocr-browser.mjs`；原图和逐例结果仅在被忽略的artifacts目录。

用户实际截图未能从浏览器连接读取，尚未复测。不能据本轮宣称已解决用户图片中的所有名称问题。下面2026-10-26结果为历史记录，源码哈希不代表当前版本。

本评估只使用脚本生成的虚构持仓截图。表格、卡片和纵向列表为通用布局，不代表已兼容任何真实金融平台。没有读取真实账户、个人截图或上传图片。

## 复现

在项目根目录运行（需要已安装 Playwright 和本机 Microsoft Edge，不下载浏览器）：

```powershell
node scripts/generate-fixtures.mjs
npm run dev -- --port 4319
```

保持 Vite 开发服务运行，在另一个终端运行：

```powershell
node tests/ocr-benchmark.mjs
```

默认访问 `http://127.0.0.1:4319/tests/ocr-harness.html`；可用 `OCR_TEST_URL` 指定端口。测试调用浏览器真实导入的 `/src/ocr.mjs` 中的 `startRecognition(canvas, onProgress)`，并逐张识别本地 PNG。工作线程和语言文件应由应用从本地提供。

可选择部分案例进行诊断，所生成报告会明确记录实际运行数量；部分结果不能当成全部 36 张结果：

```powershell
$env:OCR_CASES='table-clean,card-multiCurrency'
node tests/ocr-benchmark.mjs
Remove-Item Env:OCR_CASES
```

## 数据与指标

生成 36 张截图：3 种布局 × 12 种条件（清晰、大字、小字、低对比度、深色、模糊、水印重叠、名称截断、多币种、小额/大额小数、紧凑排版、像素噪声）。每张含 3 条虚构资产，共 108 条。币种包括 CNY、USD、HKD；金额为固定值。名称截断案例仍保留完整名称作为真值，因此名称召回下降是预期困难，金额与币种仍独立计分。

`artifacts/ocr-fixtures/groundtruth.json` 保存绘制真值；PNG 与评估报告均在忽略目录 `artifacts/`，不应进入发布包。

`artifacts/ocr-results.json` 保存每张的原始识别文本、原始候选行、置信度、错误、进度、耗时及浏览器可提供时的 JS 堆内存。堆内存不包括 OCR Worker/WASM 总内存，不能解释为峰值进程内存。每张结束立即保存，异常不会用真值补全。金额使用业务层 `parseAmount(String(value))` 进行十进制规范化后严格相等，非空值才可匹配，容差为 0，不使用浮点近似；币种严格匹配原始字段。名称只移除空白，不改字、不模糊匹配。

若只调整评分方法而保留原始 OCR 结果，可运行 `node tests/ocr-benchmark.mjs --rescore` 离线重算。该命令不会启动浏览器、不会重新识别、不修改原始文本/预测/真值、运行时间及源码 SHA，并在报告中注明 `rescored exact decimal`。

分别统计金额、币种、金额+币种、名称和完整行的微平均 precision/recall。采用多重集合一对一消耗匹配，不依赖 OCR 行顺序，重复预测计入 precision 分母。没有预测时 precision 记为 0；识别失败按零召回计入。单字段指标可诊断丢失原因，金额+币种配对和完整行指标更严格。原始预测不做任何真值替换或校正。

此文件是方法说明；实际结果以本次运行生成的 JSON 为准。尚未执行时不得声称已通过，合成基准也不能证明真实平台截图的准确率。

## 已执行结果：2026-10-26

在本机 Edge 无头浏览器上实际执行全部 36 张、108 条真值，调用本地 Tesseract 中文/英文模型，未经人工修正。最终运行时间为北京时间 21:48:25–21:48:54。36 张均完成引擎识别，0 引擎异常、0 浏览器请求错误。预测共 105 行。OCR 源码运行前后 SHA-256 相同：`5eb3e68ff60f095a7d4844093a3287e65ff67a30bb21aee32dd5dbbdda1c8bc8`。真值 SHA-256：`456c8092763a8819b95b246ee6535b0089ab6f261d31523885a6d5659675c006`。

| 指标 | 正确/预测/真值 | Precision | Recall |
|---|---:|---:|---:|
| 金额 | 104 / 105 / 108 | 99.05% | 96.30% |
| 币种 | 104 / 105 / 108 | 99.05% | 96.30% |
| 金额+币种配对 | 104 / 105 / 108 | 99.05% | 96.30% |
| 名称（仅去空白） | 91 / 105 / 108 | 86.67% | 84.26% |
| 完整行 | 90 / 105 / 108 | 85.71% | 83.33% |

上述结果已从本次真实运行的原始预测离线重算为十进制严格相等，取代早期 0.011 容差方法；各项正确数与指标均未变化。原始 OCR 输出、预测、真值、识别时间及源码 SHA 均保留，报告含 `rescored exact decimal` 标记，没有为此次评分重算重新运行 OCR。

金额或币种为空的候选仍计入预测分母，因此这些字段的 precision 是保守的候选行口径。名称截断案例仍用完整原名作为真值，没有豁免或补全。

金额+币种失败集中在两张：`card-dark` 将中文金额标签识别为 `KOSH`，没有提取 3 行；`card-overlap` 水印遮挡了第一条金额，保留候选但金额/币种为空，其余 2 条金额正确。没有猜测或回填被遮挡值。

完整行未满分共 9 张：`table-truncated`、`table-decimals`、`table-noisy`、`card-dark`、`card-overlap`、`card-truncated`、`stacked-small`、`stacked-dark`、`stacked-truncated`。除上述两个金额案例外，其余失败为名称截断或错字；不能把金额准确率当成全字段准确率。

36 张累计引擎识别 26.98 秒，单张平均 0.749 秒、中位数 0.739 秒、最慢 1.047 秒；这是本机缓存/本地文件条件下的结果，非性能承诺。浏览器报告的页面 JS 堆最高约 9.88 MiB，不含 Worker/WASM 内存。

本次基准暴露了 OCR 中文标签插入空格及卡片金额换行的解析缺口；修复后重新执行全部 36 张，并在最终补充非法逗号分组拒绝规则后再次执行全部 36 张。修复前的真实 36 张零提取结果保存在 `artifacts/ocr-results-before-label-fix.json`；首次本地 vendor 尚未准备好的失败尝试保存在 `artifacts/ocr-results-vendor-not-ready.json`。最终完整原始输出与失败样例位于 `artifacts/ocr-results.json`。这些文件不会进入生产发布包。
