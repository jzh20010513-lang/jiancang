# 支付宝同列版式错配修正

2026-10-27用户反馈：资产名称被解析为“占比”，其余字段无法对应原图。此前合成图偏向“名称、金额分列”的表格，没有覆盖真实反馈中的“名称/金额同列、收益在右侧、占比在下方”结构。不能将此前单测或合成图准确率视为真实截图验收。

## 根因与修正

- 实际OCR原文包含名称、金额、分类徽标及占比，但旧解析器把该结构当普通表格，只在数字行寻找名称，导致“占比”被创建为资产，真正的基金名称与左侧金额没有配对。
- 显式“名称/金额 + 日收益”等表头启用独立适配。支持上方名称、其下“基金/进阶理财/灵活取用”等徽标、左侧金额、右侧收益、下一行占比。文字和坐标两条路径均过滤界面标签。
- 占比结束当前条目，不能继续借用后卡金额；缺失或重复金额保留未知。几何不根据中文前缀猜测跨行基金名称，仅允许明确的短份额后缀。名称本身含“收益”不等于收益字段。
- 每张/每段新的同列表头刷新金额单位，禁止把第一段的元/万元及币种证据延续到后段。账户、日期、币种、流动性没有明确证据时保持待补；不根据支付宝、字体颜色或位置默认。
- 增加本地文字恢复入口。未识别到可靠候选时保留已有草稿；替换已有候选需用户确认。不会自动确认、写入持久存储或替换看板。

## 本轮证据

实际页面的既有OCR文字通过浏览器DOM在内存读取，没有保存到文件或仓库。在独立标签页用最终构建重新整理，6条名称与6个持仓金额均与原文独立对应位置一致，0条资产名称为“占比”，0条自动确认。该结论只验证原文→字段配对，不证明OCR原文中的每个字与原图一致，也不是重新运行实际原图OCR。

用户截图、基金名称、金额及识别全文均未纳入代码、测试、文档、日志附件或发布包。程序生成的匿名同列六条截图另行实跑浏览器OCR，验证新图片路径，不以其替代用户原图验证。

## 复现入口

- `node --test tests/alipay-text.test.mjs tests/alipay-layout.test.mjs`：匿名边界样例。
- `node tests/alipay-combined-ocr-browser.mjs`：匿名同列截图真实OCR。
- `node tests/stacked-import-browser.mjs`：本机文字恢复及失败保留。
- `npm.cmd run check`：完整单测及构建；`node scripts/audit.mjs`：静态输出和凭据特征审计。

浏览器脚本默认使用本轮4320预览，可设置BASE_URL。测试只使用虚构数据。代码仍只本地管理，不上传、不部署，不修改个人版。

最终验证：183/183单测与构建通过；匿名同列六条截图真实OCR、本机文字恢复、异步取消和既有隐私/OCR/备份工作流通过。静态审计未命中凭据特征。独立审查提出并修复了收益名称误过滤、跨基金中文续行、重复数字行、跨表头单位继承和占比未关闭卡片五类问题，修复复核相关24项测试通过。旧页面已有候选不会因磁盘构建更新而自动改变；需在新构建中重新识别或粘贴既有识别原文。
